LoRaWAN Glossary — ADR / AU915 / STM32WL

Oct 27, 2026

The big picture

A LoRaWAN device never talks to a server directly: its radio packets reach one or more gateways, the gateways forward them over the internet to a network server, and the network server hands the data to the application. ADR lives in the network server: it watches the signal quality of the device's uplinks and sends back MAC commands telling the device which data rate and TX power to use.

Stakeholder's problem sits on the link between the device's firmware (ST's stack on the STM32WLE5) and the network server (ChirpStack vs. TTN). Terms below are grouped by layer; the ones that matter most for the ADR investigation are marked (ADR).

The gateway only relays; every ADR decision comes from the network server, so swapping TTN for ChirpStack changes the commands the same firmware receives.

Network architecture

Term What it means
End device / end node The sensor itself (Stakeholder's STM32WLE5 / LSM110A board). Battery-powered, transmits rarely.
Gateway A radio receiver with an internet connection. It forwards every LoRa packet it hears to the network server and transmits downlinks back. It has no idea what the packets mean.
Packet forwarder Software on the gateway that ships packets to the server. Two common flavours: Semtech UDP (legacy, simple) and LoRa Basics Station (secure, websocket).
Network server (NS) The brain of the network. Deduplicates packets heard by several gateways, checks integrity, runs ADR, schedules downlinks, sends MAC commands. (ADR)
Join server (JS) Holds the root keys and approves OTAA joins. Often bundled inside the NS.
Application server (AS) Decrypts the user payload and delivers it to your app (MQTT, HTTP webhook, etc.).
Uplink / downlink Device → network / network → device.
Class A Device listens only in two short receive windows (RX1, RX2) right after each uplink. Lowest power. Stakeholder's device is Class A, so it can only receive ADR commands right after it transmits. (ADR)
Class B / Class C B: extra scheduled receive slots synced by gateway beacons. C: receiver always on.
The Things Network (TTN) A free, public, community-run LoRaWAN network running The Things Stack (TTS). You create an account and register devices on their hosted servers.
The Things Stack (TTS) The network-server software behind TTN; also sold as a private/commercial product.
ChirpStack An open-source LoRaWAN network server you install and run yourself (usually with Docker). No central "account"; every installation is private.

Because Stakeholder's device is Class A, every ADR change takes at least one uplink to deliver and another to acknowledge; a rejected command repeats on every uplink.

Radio

Term What it means
LoRa The physical radio modulation (chirp spread spectrum) from Semtech. LoRaWAN is the network protocol on top of it.
Chirp A signal sweeping up or down in frequency. LoRa encodes bits in chirps, which is why it survives very weak signals.
Spreading factor (SF) SF7 to SF12. Higher SF = slower, longer airtime, more range and robustness. Each step up roughly doubles airtime.
Bandwidth (BW) Width of the radio channel: 125 kHz or 500 kHz in AU915.
Data rate (DR) A numbered index combining SF + BW. In AU915: DR0 = SF12/125 kHz … DR5 = SF7/125 kHz, DR6 = SF8/500 kHz. ADR changes this number. (ADR)
Airtime / time on air How long one packet occupies the channel. Drives battery use and regulatory limits.
RSSI Received signal strength in dBm (e.g. −110 dBm). Raw power, includes noise.
SNR Signal-to-noise ratio in dB. LoRa can decode below the noise floor (down to about −20 dB at SF12). This is the main input to ADR. (ADR)
Link margin How many dB above the decoding limit a packet arrived. Big margin = the server can speed the device up or lower its power. (ADR)
EIRP Effective radiated power = TX power + antenna gain. Regulations cap EIRP, not conducted power.
TX power index Power is commanded as an index, not dBm: index 0 = max EIRP, each step = −2 dB. AU915: max EIRP 30 dBm, index 0–14. (ADR)
Duty cycle Limit on the fraction of time a device may transmit. Strict in Europe; not the binding limit in AU915/Brazil.
Dwell time Maximum time a single transmission may occupy one channel. In AU915 an optional 400 ms limit exists; when on, SF11/SF12 (DR0/DR1) are forbidden. (ADR)

If the server believes dwell time is off but the device believes it is on, the server may command DR0 or DR1 and the device will reject it.

Joining and security

Term What it means
OTAA Over-the-Air Activation. The device sends a Join-Request; the server answers with a Join-Accept and fresh session keys. The recommended method, and the ST example's default.
ABP Activation By Personalization. Session keys are hard-coded; no join. Simpler but fragile (frame-counter and reset problems).
DevEUI 64-bit unique ID of the device, like a MAC address.
JoinEUI (AppEUI in older specs) 64-bit ID of the join server the device should join through. Often all zeros on ChirpStack.
AppKey 128-bit root key shared between device and join server. Session keys are derived from it at join.
NwkSKey / AppSKey Session keys. NwkSKey signs and checks frames (MIC) and encrypts MAC commands on port 0; AppSKey encrypts the user payload. (LoRaWAN 1.1 splits the network key into three.)
DevAddr 32-bit short address assigned at join; used in every frame instead of the DevEUI.
Frame counters (FCntUp / FCntDown) Count every uplink/downlink to block replay attacks. A device reset that rolls them back gets its packets dropped.
MIC Message Integrity Code: 4-byte signature on each frame.
Join-Request / Join-Accept The two OTAA messages. The Join-Accept also carries the RX settings and, for AU915, can carry a channel list.

The AppKey itself never travels over the air; after the join, ADR state (DR, power, channel mask) resets to the region defaults.

MAC layer and ADR

Term What it means
MAC command A small control message between NS and device (not user data). Each has a request and an answer, e.g. LinkADRReq / LinkADRAns. (ADR)
FOpts / FPort 0 Where MAC commands travel: piggybacked in the frame header (FOpts, max 15 bytes) or as the whole payload on port 0.
ADR (Adaptive Data Rate) The NS tunes each device's DR, TX power and repetitions from its recent SNR history. (ADR)
ADR bit Flag in every uplink: 1 = "the network may adjust me". If 0, the device keeps its own DR/power. (ADR)
LinkADRReq NS → device: DataRate, TXPower, ChMask, ChMaskCntl, NbTrans. Several can be chained in one downlink (AU915 needs this to set 72 channels). (ADR)
LinkADRAns Device → NS: three ACK bits — power OK, data rate OK, channel mask OK. If any is 0, the device rejects the whole command and keeps its old settings. (ADR)
ChMask / ChMaskCntl 16-bit channel on/off mask, and a control field saying which block of channels the mask applies to (or special actions, e.g. 7 = turn all 125 kHz channels off). (ADR)
NbTrans How many times each uplink is sent (1–15). The NS raises it on lossy links. (ADR)
0xF "keep" value In LoRaWAN 1.0.4, DataRate or TXPower = 15 means "don't change this field". Older stacks may reject it. (ADR)
ADRACKReq Bit the device sets when it hasn't heard any downlink for a while, asking the NS to prove it's still there. (ADR)
ADR_ACK_LIMIT / ADR_ACK_DELAY Defaults 64 and 32 uplinks. After LIMIT uplinks with no downlink the device sets ADRACKReq; after DELAY more, it starts backing off. (ADR)
ADR backoff Device self-rescue: back to max power first, then step the DR down one at a time until it hears the network again. (ADR)
Installation margin Safety dB the NS keeps when computing ADR. ChirpStack default: 10 dB. Smaller = more aggressive. (ADR)
TxParamSetupReq NS → device: sets dwell time (on/off, up and down) and max EIRP. Only in regions that support it, including AU915. (ADR)
NewChannelReq / DlChannelReq Add a channel / change a downlink frequency. Not used in AU915 (fixed channel plan).
DevStatusReq NS asks battery level and downlink SNR.
LinkCheckReq Device asks "am I heard, and with what margin?"

This loop is a plausible shape for Stakeholder's "undesired behaviour": a server and device that disagree on one rule keep exchanging the same rejected command.

On AU915 the last step matters: re-enabling all 72 channels sends the device off the gateway's sub-band until the server re-sends the mask.

Regional parameters, AU915 and Brazil

Term What it means
Regional Parameters (RP002) LoRa Alliance document defining, per region, the channels, DRs, power limits and MAC-command details. Revisions (1.0.1, 1.0.3, 1.0.4…) differ in small but ADR-relevant ways.
AU915 The 915–928 MHz plan used in Brazil, Australia and much of South America. 64 × 125 kHz uplink channels (915.2–927.8 MHz), 8 × 500 kHz uplink channels, 8 downlink channels (923.3–927.5 MHz).
US915 Same channel structure but 902–928 MHz; not allowed in Brazil.
Sub-band / FSB A block of 8 × 125 kHz channels + one 500 kHz channel. AU915 has 8 sub-bands. Most gateways listen to only one, so device and server must agree on it. (ADR)
FSB1 vs FSB2 ChirpStack's default AU915 config (au915_0) is sub-band 1, channels 0–7 + 64. TTN uses sub-band 2, channels 8–15 + 65. Mixing them breaks joins and ADR. (ADR)
Hybrid mode Device firmware option that enables only one sub-band from boot. In ST's legacy stack: HYBRID_ENABLED (default 0 = all 72 channels on until the NS sends a mask).
Channel mask negotiation After join, the NS sends chained LinkADRReq (ChMaskCntl 7, then blocks 0–3) to restrict the device to the gateway's sub-band. (ADR)
400 ms dwell time in AU915 Optional limit (from Australian rules). Both ST stacks boot with uplink dwell ON (min DR = DR2, max payload at DR2 ≈ 11 bytes). It is switched only by TxParamSetupReq. (ADR)
Brazil and dwell time Brazilian networks are generally run without the 400 ms limit (worth confirming against the current Anatel rules). TTN has Brazil-specific plans (e.g. AU_915_928_FSB_2_BR, "dwell time disabled") that tell the device so. ChirpStack's AU915 configs default to dwell off. (ADR)
RX1 / RX2 The two Class A receive windows: RX1 at 1 s after the uplink on a mapped downlink channel; RX2 at 2 s on a fixed frequency (AU915: 923.3 MHz, DR8). MAC commands arrive here.
RX1 DR offset How much lower/higher the downlink DR is versus the uplink DR.

A gateway usually listens to one sub-band only, so the sub-band chosen in ChirpStack must match the gateway's radio configuration and what the device ends up using.

Specs, software and certification

Term What it means
LoRaWAN 1.0.x / 1.1 Versions of the link-layer spec (TS001). 1.0.4 is the current 1.0 line and what ST's legacy example targets; 1.1 adds roaming and split keys. The device and the NS device profile must declare the same version. (ADR)
LoRa Alliance The industry body that writes the specs and runs certification.
LoRaWAN certification Lab testing that the device behaves per spec (join, MAC commands, ADR, counters, regional rules). Needed to carry the LoRaWAN Certified mark; some operators require it.
LCTT LoRaWAN Certification Test Tool: the Alliance's tool for pre-certification testing in your own lab before going to an authorized test house.
Pre-certification Running the certification test cases yourself first, to find failures cheaply.
Device profile Settings on the NS describing a device type: MAC version, RP revision, region, class, ADR algorithm, uplink interval. A wrong profile is a classic cause of ADR trouble. (ADR)
ADR algorithm (server) Each NS has its own. ChirpStack: default, LoRa+LR-FHSS, or custom plugins. TTN: its own algorithm. Same device, different behaviour. (ADR)
LoRaMac-node Semtech's reference end-device stack. ST's legacy STM32WL stack ("LoRaWAN v2.x" middleware) is a port of LoRaMac-node 4.7.
LoRa Basics Modem (LBM) Semtech's newer end-device stack. Since STM32CubeWL v1.5.0 (Feb 2026), ST ships this instead of LoRaMac-node.
STM32CubeWL ST's software package for STM32WL chips: drivers, the LoRaWAN stack, and example projects such as LoRaWAN_End_Node. Current: v1.6.0 (June 2026).
LmHandler The "LoRaMac handler" layer in ST's legacy stack: the API your application calls (join, send, ADR on/off).
SubGHz_Phy ST's radio driver layer for the STM32WL's built-in Semtech radio.

Which column Stakeholder's code sits in is the first thing to ask them: projects started before February 2026 are almost certainly on the left one.
