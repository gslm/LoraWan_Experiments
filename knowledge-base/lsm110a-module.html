LSM110A Module Primer

Oct 28, 2026. What the LSM110A is, how it is built and used, and what that means for our ADR investigation. From the vendor's public documents and code, and the LoRa Alliance.

At a glance

The LSM110A is a small solder-down module from the Korean maker SJIT that wraps ST's STM32WLE5CC, the single-core sibling of the chip on our Nucleo. It speaks LoRa(WAN) and Sigfox, and it is the module the stakeholder's end device is built on.

Inside the module

The important detail is the single transmit line. The STM32WL radio has two power amplifiers, but the module's block diagram shows only one path into the RF switch, and the vendor's firmware is built to use the high-power amplifier only.

Two ways to use it

In option 1 the LoRaWAN stack is SJIT's closed binary and a host MCU talks to it with AT commands. In option 2 the product's own firmware runs on the module and the stack is whatever ST version the team compiled in. Which one the stakeholder uses decides where the root cause can live.

This is the module-level evidence behind hypothesis 2 in the primer: ChirpStack's ADR walks the TX power index down to 6-14, the range where ST's driver switches to the low-power amplifier. On this module that amplifier has no drawn path to the antenna, so the result depends entirely on which board file the product firmware uses.

Updating the firmware

The vendor publishes its firmware as a .bin (1.0.4, January 2024) for the UART bootloader. Our ST-LINK and STM32_Programmer_CLI work on the module too, through the SWD pads, as long as the bootloader and the Sigfox area are left alone.

Certifications

The AU915 test campaign (DEKRA, April-May 2022, report 71580RLR.003A2) passed all 29 test cases, including both LinkADRReq tests, TxParamSetupReq, and the RX1/RX2 window tests. The declared features include ADR and LinkADRReq blocks; data-rate decay is not implemented. These tests check the MAC protocol, not radiated power per TX index.

What this means for our investigation

  • First, which option they use. AT modem (SJIT firmware 1.0.x) or their own firmware on the module. This decides whether their stack can be changed at all.
  • If it is their own firmware, the board file. A radio_board_if copied from a Nucleo example (LP + HP) on this module is the strongest suspect for failures at low TX power.
  • Their middleware version. The vendor SDK carries MW 2.4.0; a newer CubeWL behaves differently in places (back-off, LinkADRReq handling details).
  • Region and channels. Check that AU915 really is set at every boot, and how the channel mask reaches the device.
  • Our lab needs an LSM110A. The vendor's evaluation board (ST-LINK connector, USB-UART, SMA) would let us run the same bench tests on the real module. Never full-erase it.
